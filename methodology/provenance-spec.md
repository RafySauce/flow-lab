# Provenance Spec (Work Edition)

The canonical frontmatter schema every artifact in this system carries. Slimmed and generalized from a private homelab schema ("DNA spec") for workplace use: the Obsidian-specific graph machinery is gone; the trust and audit fields are kept and extended.

This document is the single source of truth for the schema. When a template's embedded example and this spec disagree, **this spec wins**. Foundries never extend the schema — they flag needed changes for the operator to ratify here.

---

## The schema

```yaml
---
id: <kebab-case-unique-id>          # stable identifier; the link/reference target
title: <Human readable title>
type: <see Type enum>
artifact-version: "1.0"             # this document's own revision, independent of any tool version
created: YYYY-MM-DD
updated: YYYY-MM-DD
status: living | dead | replaced    # replaced requires superseded-by: "<new-id>"
truth-level: claimed | draft | to-review | verified | deprecated
owner: <accountable human>
source: human | human+ai | ai       # AI-involvement disclosure — see below
generated-by: <agent/skill name>    # omit if hand-authored
generated-by-version: "<version>"   # travels with generated-by
data-class: public | internal | confidential | restricted
related: []                         # sibling document ids
---
```

In an instantiated GitLab instance and in this repo alike, these fields are literal YAML frontmatter — the single surface means there is no page-property mapping (see `mirroring-protocol.md`).

## Field reference

### Identity

- **`id`** — kebab-case, unique, stable. Filenames derive from it: primer-briefs as `fp-<slug>.md` / `sp-<slug>.md`, decision-log entries as `YYYY-MM-DD-<slug>.md`.
- **`title`** — human-readable; use the document's first H1.
- **`artifact-version`** — the document's own revision number. Independent of `generated-by-version`: a document on revision 3 may have been generated by tool version 0.2.

### Lifecycle

- **`status`** — `living` (current, authoritative), `dead` (retired, no replacement, kept for record), `replaced` (requires companion field `superseded-by: "<new-id>"`).
- **`truth-level`** — the epistemic lifecycle. Four linear values plus one branch:
  - `draft` — intent or plan; not yet complete.
  - `to-review` — complete but not verified by a human.
  - `verified` — **a human confirmed it against reality.** Human-only promotion, with review evidence (see `governance-and-audit.md`).
  - `deprecated` — was verified, now stale.
  - `claimed` — (branch) external material not authored under this method, ingested as-is. A claimed artifact is never simultaneously verified.

### Provenance and disclosure

- **`owner`** — the accountable human. Every artifact has exactly one.
- **`source`** — the AI-involvement disclosure axis:
  - `human` — authored directly by a person, no AI.
  - `human+ai` — built collaboratively; a human was in the loop during authoring.
  - `ai` — produced autonomously by an agent; no human in the authoring loop. An `ai`-sourced artifact **must** pass through `to-review` and a human gate before anyone relies on it.
- **`generated-by` / `generated-by-version`** — the specific skill/agent that produced the document and its version. Both or neither.

### Governance

- **`data-class`** — the classification of the *most sensitive content in the document*: `public | internal | confidential | restricted`. Adapt the enum to your employer's classification scheme — the field is mandatory either way. Checked at intake and at every stage's Data boundary (see `governance-and-audit.md`). Everything in this public repo is `public` by definition.

### Graph

- **`related`** — sibling document ids, as a flat list. Kept deliberately simple; no wikilink/entity-graph machinery in this edition.

### Stage-context extension

Two additional fields, mandatory on `type: stage-context` only:

- **`stage`** — the stage's position (integer) within its flowspace, matching the numbered folder (`stage: 3` in `03-scope-and-dependencies/CONTEXT.md`).
- **`review-intensity`** — `heavy | light`, the U-curve review-intensity map made operational (`icp-primer.md` §3.9): how much human attention this stage is expected to need. Set once when the flowspace is scaffolded; a foundry proposes it, the operator confirms it.

## Type enum

| Type | What it is | Default truth-level |
|---|---|---|
| `specification` | A spec, plan, or schema (this document is one) | `draft` |
| `template` | A reusable mold other documents are stamped from | `verified` |
| `flowspace` | An ICM-structured workflow workspace (the hub card of one) | `to-review` |
| `stage-context` | A stage's `CONTEXT.md` within an instantiated flowspace — the six-field stage contract itself, not just its hub | `to-review` |
| `flow-primer-brief` | Crystallized flowspace intent → flow-foundry intake | `to-review` |
| `skill` | The card for a built skill (spec + adapters) | `to-review` |
| `skill-primer-brief` | Crystallized skill intent → skill-foundry intake | `to-review` |
| `decision-log` | A logged non-obvious decision (triage drop, security flag, structural call) | `verified` (records an event) |
| `exemplar` | A sanitized worked example kept for teaching | `verified` |
| `clipping` | External material captured as-is | `claimed` |

Foundries flag missing types; only the operator adds rows here.

---

## Conditional rules

Rules any validator (or reviewing human) must apply beyond the flat field list:

1. `status: replaced` requires `superseded-by`.
2. `type: clipping` implies `truth-level: claimed` and `source: ai` or external — a clipping marked `verified` is a contradiction.
3. `generated-by` and `generated-by-version` travel together.
4. `truth-level: claimed` never pairs with `source: human`.
5. `truth-level: verified` requires review evidence — a decision-log entry naming reviewer and date (see `governance-and-audit.md`). Verified without evidence is invalid.
6. `data-class` above `public` is invalid **in this repository** — such content belongs in employer tenancy.
