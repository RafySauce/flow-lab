# Flow Primer Brief — <Workflow Name>

> Intake path 1 for the flow-foundry: crystallized intent, written down *before* scaffolding starts. If you can't fill the sections below, the exploration isn't done — finish thinking before building. File the completed brief in `flow-foundry/backlog-flow-starters/` as `fp-<slug>.md`.

## Purpose

One or two sentences: what problem this workflow solves, for whom, and how often it recurs. (A workflow that won't recur doesn't earn a flowspace.)

## Trigger and cadence

What kicks off a run (an event, a date, a request) and how often runs happen.

## Stage sketch

Best current guess at the stages, in order, one line each — name + what happens there. Mark stages you're unsure about with `(?)`. Estimate review intensity per the U-curve: first and last stages heavy by default.

| # | Stage | What happens | Review intensity (est.) |
|---|---|---|---|
| 1 | | | heavy |
| 2 | | | light |
| … | | | |
| n | | | heavy |

## Data profile

The classes of data each run touches, and any stage-specific boundaries you already know (e.g., "stage 2 handles customer names — internal engines only").

## Layer-3 inventory

Capabilities the stages will lean on: existing skills to reference, logic that's one-off, and suspected gaps (candidate skill-primer-briefs).

## Surfaces

Where the primary instance will live (Confluence space/page) and which repo mirrors it.

## Open questions

Anything unresolved that the foundry must surface (not silently decide) during setup.
