# Intake Triage

## What this room is for
The front door. Every starter passes through here first to be classified and, if foreign, vetted. This is where you decide what path a thing is on before any building happens — and where you say no to material that shouldn't become a skill at all.

## Process
Pick up a starter (from /backlog-skill-starters or handed in chat). Classify it:
1. Skill-primer-brief? (structured, house-voiced intent from the thinking-partner or architect) -> clean path, route to /forge.
2. Foreign material? (URL, README, MCP entry, repo, collection) -> vet first: fetch and read it, check maintenance and provenance, run a security read against the sovereignty boundary. Pass -> route to /forge. Fail -> note why and recommend dropping.
3. Not skill-worthy? (marketing, abandoned, already-have-it) -> say so plainly, recommend dropping. Not every starter survives.

Stamp the starter truth-level: claimed on capture. Log a trace for any non-obvious triage call (especially drops and security flags) — that judgment is exactly what Hermes needs to inherit.

## What lives here
No files persist here — it is a decision room. Starters live in /backlog-skill-starters; the triage outcome is a routing decision plus a trace in /traces.

## What good looks like
A clear verdict with a reason. "Foreign repo, last commit 2 years ago, wraps a dead API -> drop" is a good triage. A starter waved through without a security read is a bad one. The discipline: vetting is required, not optional, and dropping is a legitimate, frequent outcome.
