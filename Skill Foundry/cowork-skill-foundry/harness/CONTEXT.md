# Harness

## What this room is for
Where the future Hermes skill-foundry agent takes shape. Because Hermes will inherit this entire responsibility and process, this room is unusually concrete from day one: it is not "maybe an agent someday," it is "the agent that runs this exact pipeline, drafted as we learn what the pipeline actually is." Every synthesis finding that implies an agent behavior, a routing rule, or a wiring decision lands here.

## Process
Accumulate design material as it emerges — don't force it. When the synthesis task (or a build) reveals something the agent must do, capture it: a prompt fragment, a routing heuristic, an MCP/gateway note. Over time this room assembles into a real Hermes agent spec: the skill-foundry-agent that triages, vets, normalizes, and routes skills for review.

## What lives here
- Draft agent-prompt material for the skill-foundry-agent.
- Inference-gateway routing notes (how execution-tier maps onto the Ollama -> Gemini -> OpenRouter -> frontier ladder).
- MCP wiring notes (which capabilities the agent needs as tools — fetch for foreign intake, the skill-creator engine, RNA validation).
- The handoff seam: how this agent hands a normalized skill to Cincinnatus (or, eventually, to a council review) for the verified gate.

## What good looks like
Material that a future Hermes deployment session can pick up and build from — not abstract aspiration. The test: could the Hermes session read /harness and /synthesis and know what to build? When the answer is yes, the carry-across has worked.

## Open seam
The verified human gate is the one piece that resists full automation by design — Hermes can triage, vet, and normalize, but "is this skill good enough to be verified" stays a human (or council) judgment. The harness should preserve that gate, not engineer it away. This mirrors the foundry skill's own "never self-promote to verified" rule.
